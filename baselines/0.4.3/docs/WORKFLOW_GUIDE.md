# 工作流使用指南

## 初始化入口

安装插件后，在目标项目的 Codex 新任务中调用 `$bootstrap-project-flow`。该 Skill 一步完成两件事：

1. 把项目协作文件安装到目标项目。
2. 默认让发出部署命令的当前任务认领并固定为用户可见项目中枢，标题形如 `项目中枢 · 项目名`；项目已有规范中枢、旧版中枢键或未完成认领任务时直接复用并修复已有任务。

原地认领会先使用严格的临时身份反查当前任务 ID，再完成规范命名与固定。中途失败只能恢复同一任务，不能静默新建替代中枢。若发现多个历史候选，用户必须指定唯一保留项并单独授权清理；被淘汰任务用版本化退役标题永久排除旧启动消息的再次恢复。只有用户明确要求独立中枢模式时才创建新任务；若创建仍处于排队状态，等待它出现在任务列表后再继续，不要重复调用 bootstrap。

插件安装、直接复制模板或手动运行 `scripts/install.ps1`、`scripts/install.sh` 只会安装文件，不能调用 Codex 桌面的任务 API，也不会创建中枢任务。当前没有“安装完成即零点击运行”的钩子；完整初始化需要在 Codex 中显式调用一次 `$bootstrap-project-flow`。

完整的新安装会生成 `.project-flow/manifest.json`。若目标已经含有受管文件但没有清单，安装器会继续跳过已有文件，却不会猜测它们的来源并创建清单；应使用 `$upgrade-project-flow` 明确确认旧版基线后纳管。

在 POSIX 环境中，安装与升级脚本需要 `python3`；PowerShell 入口不依赖 Python。

## 任务感知升级

在更新插件后，必须在需要升级的目标项目中新建 Codex 任务，再调用 `$upgrade-project-flow`。Skill 只接受调用它的当前任务所属项目；当前项目 ID 或规范化工作目录与目标不一致时，会在读取或操作其他项目前停止。只要求计划时，Skill 仍然只运行当前项目的文件级只读计划，不创建或修改任务。明确要求应用升级时，当前新任务成为临时升级协调器，并自动执行以下流程：

1. 穷尽发现同项目任务，确认唯一永久中枢和升级前活动任务快照。
2. 激活任务创建屏障；普通执行任务暂时不能创建。
3. 创建一个独立、用户可见的升级执行任务，由它运行文件升级和验证。
4. 把升级器实际返回的事务 ID 绑定到协调流程，并让永久中枢重新读取新版规则、完成版本握手。
5. 快照为空时，在中枢原始握手成功后直接解除屏障，不创建继任；否则对仍需继续的旧任务，在安全点取得交接、归档前任并创建继任。
6. 每次等待后完整分页读取精确任务历史，只从原始 `agentMessage` 第一行验证握手。相同终止轮次连续三次完整快照且经过有界等待后才算稳定空响应；相同合法重复握手幂等折叠。继任连续两次稳定空响应时，最多创建一个代次加一的补偿继任；全部闭环后解除屏障。

升级协调器和升级执行任务都占五个活动名额；阻塞、等待和排队状态仍占名额。创建只返回排队 ID 时等待且不重试。任务枚举无法证明穷尽、唯一中枢不明确、活动名额不足、文件事务失败、版本或事务不匹配时，屏障保持失败关闭并报告，不会回退到协调器执行。

v2 继任键绑定精确项目、中枢、前任、代次、目标工作流版本和文件事务；继任必须返回绑定相同字段的版本握手。等待结果只负责唤醒；任务摘要、预览、标题、`latestAssistantMessage`、状态说明、推理摘要、工具输出、空等待结果和提示回显都不能代替原始消息或证明空响应。工作树任务只有在存在已经授权的可传递检查点和精确起始状态时才自动继任，否则保持未协调并报告，不能猜测分支或切换到其他环境。

## 中枢运行入口

认领或复用完成后，该用户可见任务就是日常项目中枢；`.agents/prompts/00_project_hub.md` 是其中的运行提示，不承担初始化。运行态不再次调用 `$bootstrap-project-flow`，也不创建、派生或转交到另一个中枢。

项目中枢先进入只读 Work，再确认执行边界并提供编号授权项。

典型顺序：

1. 只读理解当前问题与相关实现。
2. 确认目标、范围、不做项、环境和验收标准。
3. 分别列出修改、检查、构建、测试、文档同步、提交和推送；每个执行编号项都注明需要创建对应的用户可见活动执行任务。
4. 用户选择编号后，中枢创建对应活动执行任务；选择编号只授权创建任务，不授权中枢执行。
5. 中枢等待、协调活动任务并按实际证据汇总结果。

## 最多五个后续活动执行任务

项目中枢本身是长期协调入口，不计入后续执行任务名额。中枢之外默认最多维护五个用户可见活动执行任务，阻塞、等待和排队中的任务仍各占一个名额。无冲突任务可以并行，高风险操作和外部操作仍串行。任务管理能力不可用、任务创建失败、创建结果无法继续管理或无法确认任务身份时，中枢停止并报告，禁止回退到中枢执行；隐藏子代理不得替代用户可见活动执行任务。

## 执行任务轮换

执行任务按“代次”保持聚焦：一代只处理一个里程碑或一轮修改与验证。默认在第 6 个实质执行轮次评估，最迟在第 10 个轮次到达安全点时轮换；里程碑完成但仍有后续、上下文出现压力或用户明确要求时可提前轮换。

自动轮换是独立授权项，只继承同一目标、范围、环境、验收标准和已授权动作。顺序固定为：

1. 前任停止新增操作，在安全点生成执行交接包。
2. 中枢校验必填字段并确认收到。
3. 中枢归档前任并确认活动任务总数仍未超过五个名额。
4. 中枢用精确项目 ID、中枢任务 ID、前任任务 ID 和正整数代次生成 `[codex-project-flow:execution:v1]` 轮换键，把完整键放在继任首条用户消息的第一行，并附上交接包。
5. 继任重新读取规则、检查实际工作区后继续下一原子步骤。

创建失败且没有任何任务 ID 时恢复前任；只返回排队 ID 时保留完整轮换键并等待，不重试创建也不恢复前任。排队任务物化后必须穷尽任务分页，把固定项和普通项按任务 ID 合并，读取同项目任务的首条用户消息；结构化委派消息只取 `codexDelegation.input` 第一行，其他消息只取纯文本第一行，并只用完整轮换键精确恢复唯一继任。无法证明穷尽时停止，零匹配继续等待，多匹配停止报告歧义。交接包是短期检查点，不写入项目状态。独立 worktree 中的未提交改动不会自然转移，必须先形成经授权的可传递检查点。

## 何时回到 Work

出现以下任一变化时停止执行并重新确认：

- 工作范围变化；
- 接口或协议变化；
- 目标环境变化；
- 验收标准变化；
- 新增未授权工作项。

## 长期状态

`docs/PROJECT_STATE.md` 是唯一动态项目状态，只包含：

- 当前目标；
- 当前进展；
- 重要结论；
- 下一步。

只有长期状态确实变化且文档同步已获授权时，才调用 `$project-workflow-manager`。该 Skill 不负责任务路由、需求确认、授权、检查、构建或测试。

## 升级已安装工作流

插件更新与项目文件升级是两个层次。更新插件后，在目标项目的新任务中调用 `$upgrade-project-flow`：它只升级当前任务所属项目，不支持从别的项目跨项目代办。默认只生成计划；明确应用后由任务感知升级协议自动创建升级执行任务并协调旧版活动任务。没有活动任务时走快速路径，不创建无意义的继任。插件所有的工作流内容在本地与上游同时改变时自动采用新版；`AGENTS.md` 的“项目事实”章节和 `docs/PROJECT_STATE.md` 作为项目内容保留。

`0.2.0` 及其他没有安装清单的项目必须显式声明旧版基线。升级器只有在基线可确认、未决冲突已处理、计划验证通过并完成备份后才应用；没有旧基线的新增路径若已被不同内容占用，仍停止并生成冲突材料。人工保留这类未决冲突需要逐路径显式接受。manifest 最后写入，失败时回滚。安装器的强制覆盖只用于明确重置，不代替升级。

## 结果回传

仅在需要协调后续、要求用户选择或用户明确要求时，使用 `.agents/prompts/08_result_handoff.md`。普通完成报告保留在当前任务中。

## 项目定制

- 在 `AGENTS.md` 增加少量稳定项目事实和项目特有边界。
- 在 `.agents/workflow.json` 调整规则、SOP 和状态路径。
- 在开发 SOP 补充真实环境约束与已有验证入口。
- 更具体的模块规则放在对应目录的 `AGENTS.md` 或 README 中。
