# 本地项目记忆

计划、执行和继任任务使用本 Skill；永久中枢只读两文件，不替用户制定计划或写工作进展。路径以机器契约为准，默认同放在 `docs/PROJECT_PLAN.md` 与 `docs/PROJECT_STATE.md`。

## 读取与记录

启动先读规则和两文件，核对工作区、当前步骤、用户已确认范围及续接身份。保留其他请求和仍有效内容；更新前重读并合并，哈希冲突时重新合并而非覆盖。

计划只有“目标、总体进度、任务步骤”，步骤使用稳定编号 `- [ ] S01 | 内容`。目标和步骤由用户讨论确认；确认前标为草案。总体进度由已验收勾选数派生，只有本轮明确的人类验收才能勾选；自动测试成功、模型说完成、暂停或归档都不算验收。

状态记录具体进展、重要决策、工作产物与路径、本轮和历史验证来源、阻塞、待验收、未完工作和下一步；续接还记录 requestId、代次、精确真实或 queued 任务身份、工作区、安全点及必读文件。并行请求分开记录，保留未涉及的条目，不复制完整聊天或日志。旧状态结构可保留，不为套新模板删除有效内容。

计划访谈按协议的 **grilling 主动访谈** 节推进；状态保留已确认决定、待查事实、未决节点及依赖、已问未答问题、下一轮可问项和共同理解是否已获确认。继任从这些未决项恢复，不把推荐答案当作用户决定，也不重复已确认的访谈。

有意义进展、用户验收、暂停或创建继任前例行保存；此同步由当前工作流授权，无需逐文件草稿批准。目标、步骤和执行范围实质变化仍与用户确认。文件记录不提供执行授权，历史验证不代表当前验证。

## 本地工具

工具为本 Skill 目录下的 `scripts/project-memory.py`，只做本地持久化，归档和创建聊天由原生任务工具处理。调用 `python3 <script> <command> --project <exactRoot>`；Windows 使用可用的 Python 3 入口。成功输出 JSON，失败非零退出。以实际 `--help` 为参数依据。

- `read`：读取两文件、`sha256:<64hex>` 前置哈希及规划登记。
- `save --state-file <contentFile> --expected-state <hash>`：以最新读取的哈希保存已合并状态。
- `save-plan --plan-file <planContentFile> --state-file <stateContentFile> --user-confirmation <exactHumanText> --expected-plan <hash> --expected-state <hash>`：用户确认目标和步骤后，原子保存计划与已合并状态并派生总体进度，保留已有验收步骤且不新增勾选。工具不能鉴别人类确认，不把此命令当逐文件审批；旧计划格式不支持时读取原文并先与用户确认规范化。
- `accept --step S01 --user-acceptance <exactHumanText> --expected-plan <hash> --expected-state <hash>`：幂等同步步骤勾选、总体进度和状态验收记录。工具不能判断文字是否真的来自人类；调用者必须核对当前用户明确验收及对应步骤，不能把猜测或自动结果当参数。
- `recover`：处理已登记的中断写入；仍有冲突先停止，不能丢弃日志或覆盖新内容。
- `planning-begin`、`planning-bind`、`planning-resolve`：只供已授权 bootstrap/upgrade 的唯一规划聊天防重复登记；具体步骤见相应插件 Skill。
- `planning-rebind`：正式中枢替代全部确认后，只更新原规划登记的中枢绑定，保留相同任务/token；原规划为 queued 亦须核对可信原始创建证据。旧绑定警告不阻止业务记忆读取，也不授权创建另一个规划聊天。
- `planning-continue`：已授权的计划讨论续接中，先把唯一创建意图与所得继任身份保存到状态，再用精确根 token、前任身份和预期代次 CAS 推进同一规划登记；相同交接可幂等重试，不能覆盖其他继任。成功后才允许归档前任，queued 继任仍用 `planning-resolve` 解析。具体参数读 `--help`，工具不授权续接或管理聊天。

工具拒绝并发旧哈希、危险路径和未恢复事务。内容文件用获授权文件编辑工具准备；无 Python、保存失败、事务待恢复或结果不确定时，不得归档、创建继任或宣称已保存。记录实际路径和保存结果。

## 暂停、继续与验收

先按 `.agents/WORKFLOW_PROTOCOL.md` 识别用户意图。含糊归档先保存，再问继续或暂停，不直接管理聊天。明确继续先保存完整检查点及唯一创建意图，新任务原始提示要求重读两文件且等精确前任归档后才执行；创建身份立即保存，失败不重复创建。明确暂停只保存再归档，不创建下一任务。

用户验收时只勾选请求明确映射的步骤，未映射请求只保存状态；验收记录写入后重读并保存已合并的状态，消除该请求过时的待验收描述。保存全部成功后才处理归档，不自动开展下一步骤；验收已完成的请求不创建“继续”继任，含糊意图先澄清。保存或验收同步失败先恢复本地文件，聊天保持可恢复。文件格式使用 Markdown，H1 起始、标题逐级递进，只校验本次更新文档；任务动作和原生工具结果仍按协议核对。

## Drawio 评审记录

Drawio 请求按协议与 `$drawio-review` 保存文件/page、图稿检查点、已批准完整文案及来源、文案/图形/整体各自认可范围、待审项，以及本轮结构与视觉检查和聊天图片展示结果。记录获准导出的范围；默认不保存图片或截图缓存。恢复时重读当前图稿并核对检查点，保留用户手动修改，不用历史图稿覆盖最新文件。局部认可和设计认可均不替代总体步骤验收或后续实施授权。
