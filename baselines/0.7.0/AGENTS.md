# Codex 项目协作规则

适用于整个 `<PROJECT_NAME>` 项目；更深目录的 `AGENTS.md` 可增加局部规则。

## 项目事实

- 只记录少量、稳定且影响实施判断的事实；未知内容不得猜测。

## Work 与执行

- 本节和 `docs/PROJECT_STATE.md` 属于项目内容，升级时保留；其他托管内容采用新版。
- Work 只分析、澄清和设计。执行前确认目标、范围、不做项、环境、验收与授权；任一变化即回到 Work。
- 角色步骤读取 `.agents/WORKFLOW_PROTOCOL.md`；名额、轮换、恢复上限和身份模板读取 `.agents/workflow.json`。
- 按模块读取最近规则和实际入口。活动任务保留无关改动，只在实际环境执行已授权范围。
- 报告执行位置、操作、本轮证据和未覆盖项；计划、代码存在和历史结果不能替代本轮验证。

## 中枢与授权

- 中枢只分析、澄清、设计、编号、创建、等待、协调用户可见活动任务并汇总；不得修改或检查文件、构建、测试、同步文档、提交、推送或执行外部操作。
- 修改、检查、构建、测试、文档同步、提交、推送和轮换分别编号，并明确创建对应用户可见任务。用户选择编号只授权创建该任务，不授权中枢执行。
- 中枢永久存在且不占执行名额；名额占用、并行与串行策略以机器契约为准。
- 任务管理不可用、创建失败、结果不可管理或身份不可确认时停止。禁止中枢回退执行；隐藏子代理不得替代用户可见任务。
- 一次性要求不成为长期授权；文档同步、提交、推送和长期机制变更均需明确授权。

## 执行、轮换与升级

- 轮换只延续相同目标、范围、环境、验收和授权；在机器契约规定的轮次评估并于安全点按统一协议交接。
- 中枢确认交接后先归档前任再创建继任。无真实 ID 时按协议恢复；排队身份不得重复创建。继任重读规则、核对工作区，历史验证只算历史证据。
- 独立 worktree 仅在存在已授权可传递检查点时轮换。
- `$upgrade-project-flow` 只处理调用任务所属当前保存本地项目。身份或规范路径不匹配时，在读取或操作其他项目前停止。
- 应用升级使用可见协调器和独立可见执行器；文件变化、验证与回滚只由执行器完成。协调器只协调且占名额，屏障期间禁止普通创建。
- 插件托管内容采用新版；“项目事实”和项目状态保留；未托管碰撞停止。事务成功后按已部署契约完成中枢和必要继任握手；失败保持屏障，禁止重复事务或角色回退。
- 证据、观察、截止和恢复均按统一协议及机器契约；未完成协调只报告待续。

## 项目状态

- `docs/PROJECT_STATE.md` 只记录当前目标、进展、重要结论和下一步，不提供授权或本轮验证证据。
- 仅在长期状态实质变化且文档同步获授权时使用 `$project-workflow-manager`。
