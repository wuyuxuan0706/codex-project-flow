# Codex 工作流运行协议

本文件定义 `<PROJECT_NAME>` 的角色步骤。通用授权边界以 `AGENTS.md` 为准；所有精确数值、策略开关和身份模板以 `.agents/workflow.json` 为准。任务只执行与自身角色相符的章节。

## 共同身份与证据

- 当前保存本地项目的精确 `projectId` 和规范路径是唯一边界；按机器模板逐字段生成身份，不得模糊匹配。
- 升级握手只接受已知任务原始 `agentMessage.text` 第一行；等待、摘要、预览、标题、推理、工具输出和提示回显均非证据。
- 身份、边界、能力或结果不可确认时停止；禁止中枢、协调器或隐藏代理替代执行任务。

## 项目中枢

启动时读取 `AGENTS.md`、机器契约、本协议和项目状态，确认自身是唯一永久中枢；身份不唯一即停止。中枢只做机器契约允许的协调动作，每个执行编号创建对应用户可见任务，并依据 `tasks` 策略管理名额。创建、排队、恢复或身份确认失败时停止，不自行执行。

执行结果通常留在活动任务；需要协调、用户选择或用户明确要求时，中枢才汇总目标、修改、本轮验证、风险与下一步。对已知升级协调器的当前事务请求，中枢重读已部署规则、核对项目/版本/事务，并按机器模板返回原始握手。协调未完成时不得解除屏障或执行文件工作。

## 执行任务轮换

轮换须独立授权，且目标、范围、不做项、环境、验收和已授权动作不变；独立 worktree 还须有已授权可传递检查点，否则返回 Work。轮次门槛读取机器契约。

前任提交代次和任务 ID、执行边界、实际工作区、已完成修改、本轮与历史证据、未覆盖项、剩余步骤、风险、安全点、必读文件及 worktree 检查点；不得复制完整日志或把交接写入项目状态。

中枢确认完整后：

1. 按当前场景的机器模板生成完整继任首行。
2. 先归档已知前任，再创建对应继任。没有真实任务 ID 时恢复前任；排队身份保留同一键等待且不得重建。
3. 继任按完整首行恢复唯一身份，重读规则并核对实际工作区；前任验证仅为历史证据。
4. 普通继任不发送升级握手；升级继任核对版本、事务和代次，再按机器模板返回原始握手。

## 升级协调

应用前，协调器读取 `pluginRoot` 中目标版本的本协议、机器契约和 Skill 协调契约；不得要求旧目标项目预先存在新版协议。文件事务验证成功且 manifest/事务核对一致后，才改读目标项目已部署的 `AGENTS.md`、机器契约和本协议，后续握手、继任与屏障解除均由已部署契约控制。

1. 限定调用任务所属项目，穷尽同项目用户可见活动任务并固定快照，激活普通创建屏障。
2. 创建独立可见执行器；文件修改、检查、验证和回滚只由执行器完成。
3. 协调器只读核对事务、验证器、manifest 版本和事务 ID，再取得中枢握手。
4. 按快照和机器快速路径决定是否创建继任；需要继任时逐一安全交接，先归档前任再创建并取得握手。
5. 最终完整扫描；仅在执行器、中枢和所有必要继任精确确认后解除屏障。

阶段进入或恢复时完整分页读取且禁用工具输出；等待只负责唤醒，随后按机器配置增量读取。补发、补偿、失败或释放前再完整扫描；相同合法握手幂等折叠。稳定空响应、补发/补偿上限和单调截止均读取机器契约。

到期保留屏障并报告事务、确认项和待续项。恢复时复用 manifest、事务、任务身份与握手，只继续未决阶段；禁止重复文件事务。身份、消息、管理、验证或恢复失败时保持屏障并停止。
