# Codex 项目协作规则

适用于整个 `<PROJECT_NAME>` 项目；更深目录的 `AGENTS.md` 可增加局部规则。

## 项目事实

- 在这里记录少量、稳定、会影响实施判断的事实。
- 临时进度、阻塞和推测不属于项目事实；未知内容不得猜测。

## 读取与 Work

- 本节和 `docs/PROJECT_STATE.md` 属于项目内容，升级时保留；其他托管内容采用新版。
- Work 只读：分析、澄清、设计。执行前读取 `.agents/workflow.json` 和 `docs/DEVELOPMENT_SOP.md`；按模块读取最近的规则与文档，不无差别遍历。
- 目标、范围、不做项、环境或验收标准变化时停止执行，回到 Work 重新确认。

## 中枢与授权

- 项目中枢只能分析、澄清、设计、编号、创建、等待、协调用户可见活动任务并汇总；不得修改文件、检查、构建、测试、同步文档、提交、推送或执行外部操作。
- 修改、检查、构建、测试、文档同步、提交、推送和任务轮换分别编号；每个执行项明确要求创建用户可见活动任务。用户选择编号只授权创建对应任务，不授权中枢执行。
- 中枢永久存在且不占名额；其外最多五个活动任务，阻塞、等待和排队仍占名额。无冲突任务可并行，高风险和外部操作串行。
- 任务管理不可用、创建失败、结果不可管理或身份不可确认时停止并报告。禁止回退到中枢执行；隐藏子代理不得替代用户可见活动任务。
- 一次性要求不自动成为长期规则；文档同步、提交、推送和长期机制变更均需明确授权。

## 执行与轮换

- 活动任务只执行已授权范围，保留无关改动，报告实际证据和未覆盖项；未运行的验证不得称为通过。
- 轮换只延续相同目标、范围、环境、验收标准和已授权动作。第 6 个实质轮次开始评估，最迟第 10 个轮次在安全点按 `.agents/prompts/09_execution_handoff.md` 交接。
- 中枢确认交接后先归档前任再创建继任。创建无 ID 时恢复前任；只有 `clientThreadId` 时视为排队且不得重建。继任按完整首行键恢复并重新读取规则、核对工作区。
- 独立 worktree 只有存在已授权的可传递检查点时才能轮换。

## 工作流升级

- `$upgrade-project-flow` 只处理调用任务所属的当前已保存本地项目。项目 ID 或规范路径不匹配时，在读取或操作其他项目前停止。
- 应用升级授权临时可见协调器创建一个可见升级执行任务及同一事务所需继任。协调器只协调且占名额；不得执行文件工作。屏障期间禁止普通任务创建。
- 插件内容采用新版；“项目事实”和项目状态保留；未托管路径碰撞停止。文件事务成功后，中枢和必要继任必须确认相同版本与事务，失败时保持屏障且禁止回退。
- 握手只认精确任务原始 `agentMessage` 第一行。等待结果只负责唤醒；进入或恢复阶段完整扫描一次，之后只读最新三轮，补发或失败前再完整扫描。工具输出不读取也不作为证据。
- 同一终止轮次三次快照、间隔 1 秒和 2 秒后仍无原始消息才算稳定空响应；期间发现有效握手立即接受。同一任务的完全相同合法握手幂等折叠。
- 中枢只补发一次；继任只补发一次并最多创建一个补偿继任。零任务快照在执行器和中枢握手成功后直接解除屏障。单次协调尝试最长 60 秒；到期保持屏障并报告待续，恢复时不得重做文件事务。

## 项目状态

- `docs/PROJECT_STATE.md` 只记录当前目标、进展、重要结论和下一步，不提供授权或本轮验证证据。
- 只有长期状态实质变化且文档同步已获授权时，才使用 `$project-workflow-manager` 更新。
