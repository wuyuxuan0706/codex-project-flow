# 工作流使用指南

## 初始化入口

安装插件后，在目标项目的 Codex 新任务中调用 `$bootstrap-project-flow`。该 Skill 一步完成两件事：

1. 把项目协作文件安装到目标项目。
2. 通过 Codex 桌面任务能力创建并固定用户可见的项目中枢任务，标题形如 `项目中枢 · 项目名`；项目标识与规范标题已有匹配任务时直接复用，已创建但尚未完成命名的任务则按启动消息中的中枢键恢复，随后取消归档并确保固定。

若任务创建仍处于排队状态，等待它出现在任务列表后再继续，不要重复调用 bootstrap。串行重复调用只在规范标题和中枢键均不存在时创建新中枢。

插件安装、直接复制模板或手动运行 `scripts/install.ps1`、`scripts/install.sh` 只会安装文件，不能调用 Codex 桌面的任务 API，也不会创建中枢任务。当前没有“安装完成即零点击运行”的钩子；完整初始化需要在 Codex 中显式调用一次 `$bootstrap-project-flow`。

## 中枢运行入口

创建或复用完成后，打开该用户可见项目中枢任务开始日常工作。这个任务本身就是中枢；`.agents/prompts/00_project_hub.md` 是其中的运行提示，不承担初始化。运行态不再次调用 `$bootstrap-project-flow`，也不创建、派生或转交到另一个中枢。

项目中枢先进入只读 Work，再确认执行边界并提供编号授权项。

典型顺序：

1. 只读理解当前问题与相关实现。
2. 确认目标、范围、不做项、环境和验收标准。
3. 分别列出修改、检查、构建、测试、文档同步、提交和推送。
4. 用户选择编号项后执行。
5. 按实际证据报告结果。

## 单后续活动执行任务

项目中枢本身是长期协调入口，不计入后续执行任务名额。默认最多维护一个由中枢协调的用户可见后续活动执行任务，阻塞和等待仍占用该名额。具备任务管理能力时使用该能力维护执行任务，但不另建中枢；不具备时在当前中枢任务继续，不假装创建了独立任务。

## 何时回到 Work

出现以下任一变化时停止执行并重新确认：

- 工作范围变化；
- 接口或协议变化；
- 目标环境变化；
- 验收标准变化；
- 新增未授权工作项。

## 长期状态

`docs/PROJECT_STATE.md` 是唯一动态项目状态，只包含：

- 当前目标；
- 当前进展；
- 重要结论；
- 下一步。

只有长期状态确实变化且文档同步已获授权时，才调用 `$project-workflow-manager`。该 Skill 不负责任务路由、需求确认、授权、检查、构建或测试。

## 结果回传

仅在需要协调后续、要求用户选择或用户明确要求时，使用 `.agents/prompts/08_result_handoff.md`。普通完成报告保留在当前任务中。

## 项目定制

- 在 `AGENTS.md` 增加少量稳定项目事实和项目特有边界。
- 在 `.agents/workflow.json` 调整规则、SOP 和状态路径。
- 在开发 SOP 补充真实环境约束与已有验证入口。
- 更具体的模块规则放在对应目录的 `AGENTS.md` 或 README 中。
