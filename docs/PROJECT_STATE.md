# 项目状态

## 当前目标

- 发布并长期维护 `0.4.1`：在既有升级屏障、版本握手和自动继任基础上，让插件内容冲突自动采用新版，同时保护项目内容。

## 当前进展

- 项目中枢规则已收紧为仅分析、澄清、设计、编号、创建、等待、协调用户可见活动执行任务及汇总结果；文件修改、检查、构建、测试、文档同步、提交、推送和外部操作均禁止回退到中枢。
- 每个执行编号项都要求创建对应的用户可见活动任务；用户选择编号仅授权创建该任务。任务管理不可用、创建失败、结果无法继续管理或身份无法确认时立即停止并报告，隐藏子代理不得替代活动任务。
- 项目中枢不占任务名额；活动执行任务上限已调整为 5，阻塞、等待和排队任务仍各占名额。无冲突任务允许并行，高风险与外部操作保持串行。
- 已保留完整不可变 `0.3.0` 基线，并新增 `0.3.0-to-0.3.1` 与 `0.2.0-to-0.3.1` 单跳迁移描述；升级器按安装版本选择描述文件，事务清单统一规范化换行并在写入后核对哈希。
- 已建立不可变 `0.3.1` 与 `0.4.0` 基线；`0.2.0`、`0.3.0`、`0.3.1` 和 `0.4.0` 均通过显式单跳描述直接升级到 `0.4.1`。
- 任务感知升级由临时用户可见协调器实施：先快照活动任务并激活创建屏障，再创建独立升级执行任务；文件事务成功后自动创建必要继任并核对中枢与任务版本握手。
- 升级清单声明文件所有权：插件内容双向修改时自动采用新版；`AGENTS.md` 的“项目事实”章节受保护合并，`docs/PROJECT_STATE.md` 永不覆盖；未知新增路径碰撞继续失败关闭。
- PowerShell 与 POSIX 全量回归、模板结构校验、插件清单校验和两个 Skill 快速校验均已实际通过；POSIX 在当前 Windows/MSYS 环境按能力跳过了无法成立的权限与符号链接故障注入。

## 重要结论

- Codex 没有插件安装完成事件；完整初始化仍由用户显式调用一次 bootstrap Skill 触发，调用它的任务本身就是默认中枢。
- 更新插件和升级已复制到项目中的工作流文件是两个步骤；项目升级必须通过 manifest、不可变基线、所有权声明和逐文件 B/L/N 判定完成，不能用强制安装代替。
- 项目中枢永久保留且不占活动任务名额；所有实际执行必须由用户可见活动任务完成，失败时不得改由中枢或隐藏子代理继续。

## 下一步

- 在真实已安装的项目先运行只读升级计划，审查 B/L/N 与所有权判定后再应用 `0.4.1`，并在 Codex 应用内完成任务协调验收场景。
- 在新项目验证最多五个活动执行任务的并行协调、排队占位和失败关闭行为。
- 持续保留旧版不可变基线，并为每个受支持的直接升级路径提供显式单跳迁移描述。
