# 项目状态

## 当前目标

- `0.11.0` / schema 10：永久中枢只负责请求初始理解、首次授权和创建唯一执行任务；执行任务负责全部后续交互、文档评审、修改循环、完成验收与自归档。

## 当前进展

- 请求在真实任务 ID 或 queued `clientThreadId` 建立后完成控制权移交，中枢不再处理该 `requestId`。
- 修改或范围变化由原执行任务重新输出理解和执行项，确认后在相同任务、`requestId` 和 generation 中继续。
- 所有新建或修改的 Markdown 都先由原执行任务提交完整纯文本草稿；用户精确批准后才能写入。
- 完成结果被否决时原任务直接进入修改循环；用户同意后由原任务精确归档自身。
- `baselines/0.10.0` 用于支持已部署 `0.10.0` 项目升级；最低支持源版本仍为 `0.8.3`。
- PowerShell/POSIX validator、请求执行模型、Bootstrap、Skill 和完整回归的最终结果待实际运行后，另行形成完整草稿并提交用户评审。

## 重要结论

- 中枢是请求启动入口，不是后续消息转发、范围确认、验收或归档层。
- 执行任务从初始移交后拥有该请求的完整生命周期，不为修改轮次、文档评审或完成否决创建第二个任务。
- 初始执行授权、文档草稿批准和最终完成验收是三个独立决定，不能互相替代。
- 文件引擎不能认证真实聊天批准；工作流通过机器契约、运行协议、Skill 和行为测试失败关闭。
- 本轮不执行 commit、push、tag、GitHub Release 或其他外部发布。
