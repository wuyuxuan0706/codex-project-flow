# 项目状态

## 当前目标

- 发布并长期维护 `0.3.0`：部署任务默认原地成为永久项目中枢，已部署项目可安全升级，单个执行任务按有界代次轮换。

## 当前进展

- `$bootstrap-project-flow` 已改为默认认领发出部署命令的当前任务，并保留已有中枢恢复与显式独立中枢兼容模式；发现过程必须穷尽任务列表，重复候选或并发认领会停止并恢复当前任务，用户明确清理的重复中枢会获得任务侧退役标题，不再因旧启动消息被重新识别。
- 已新增 11 项受管文件清单、真实 `0.2.0` 基线、声明式迁移和 `$upgrade-project-flow`；支持只读计划、冲突暂存、逐路径接受人工合并结果、事务应用、失败回滚与显式回滚。
- 全新安装会生成 `.project-flow/manifest.json`；安装写入或最终校验中途失败会恢复已替换文件；旧安装没有清单时必须显式确认 `0.2.0` 基线，`docs/PROJECT_STATE.md` 始终采用 `seed_once`。
- 执行任务从第 6 个实质轮次开始评估、最迟第 10 个轮次在安全点交接；前任归档、继任排队和失败恢复均有确定状态机，排队继任用首条用户消息中的版本化 `rotationKey` 精确恢复。
- POSIX 全套回归、模板结构校验、两个 Skill 校验和插件清单校验已实际通过；PowerShell 对等实现已完成，但当前环境没有 `pwsh`，尚未实际执行 PowerShell 测试。

## 重要结论

- Codex 没有插件安装完成事件；完整初始化仍由用户显式调用一次 bootstrap Skill 触发，调用它的任务本身就是默认中枢。
- 更新插件和升级已复制到项目中的工作流文件是两个步骤；项目升级必须通过 manifest、不可变基线和逐文件 B/L/N 判定完成，不能用强制安装代替。
- 项目中枢永久保留且不占后续执行任务名额；短期轮换交接不写入长期项目状态，继任必须重新核对规则和实际工作区。
