# 指导式编程

本技能采用一种分工：用户写入项目代码，Codex 在聊天中提供方案、解释、检查和代码自测。保持用户对代码结构、接口及实现逻辑的参与，不提供自动实现模式或模式切换入口。

## 从实际项目和已确认设计开始

读取当前任务范围、适用项目规则和实际相关文件，复用已确认的需求与架构。尚未确定架构时，先一起明确模块职责、依赖方向、数据流和必要的接口边界；说明选择及取舍，等用户确认相关架构后再进入实现。已有确认只补问缺项或用户要调整的部分。

环境事实由 Codex 在范围内只读核实，不让用户代查能直接读取的信息。不要因为存在一份计划书就假定架构已确认，也不要为固定流程重复讨论已有决定。

## 每轮只完成一个小目标

1. 选一个有明确边界的小目标，例如一个接口、一段关键逻辑或一个验证场景，说明它与架构的关系和本轮完成条件。前置设计未定时，本轮先讨论相关决策，不展开整模块代码。
2. 带用户推演本轮的输入输出、接口约定、数据结构、主要分支及必要的失败处理。按用户理解程度解释原因，用具体输入、执行过程或小例子说明；会改变架构或接口含义的选择先取得确认。
3. 在聊天中给出本轮所需的小段代码，标明实际文件路径、所属类型或函数、插入或替换位置及依赖。说明关键逻辑和预期结果，使用户能选择性复制修改；不要只给一份大补丁或一次铺开整个模块。
4. 停在等待用户修改的位置。用户提问时留在当前小目标回答，必要时修订方案；不把提问、沉默、经过时间或助手的判断当作继续指令。
5. 用户表示已修改或要求检查后，重新读取实际代码，核对用户采用、修改或省略了哪些建议，再按下节检查和自测。用户未复制完整建议不自动算错误，按已确认目标和接口判断。
6. 汇报本轮检查、自测、未覆盖项及仍需用户处理的内容，然后等待用户明确继续。自测通过不自动进入下一小目标；用户只说“继续”也不证明代码已写入、测试通过或完整步骤已验收。需要时先核实当前实际状态。

“一个小目标”按可理解、可验证的行为划分，不强制一个函数或固定行数。解释足以支持用户做决定；不要用连续追问测验用户，或要求用户重复已经表达清楚的理解。

## 代码写入与其他操作

- Codex 不直接创建、编辑或覆盖项目源代码、项目测试代码和用于实现功能的配置，不运行补丁、代码生成或自动修复来代替用户写入。修正意见和新增测试代码仍在聊天中提供，由用户写入后重新检查。
- 安装依赖、环境改动、独立构建、提交、推送、部署及其他项目操作由 Codex 给出目的、准确步骤和预期结果，用户执行；不要在后台代做这些操作。
- 可以在当前授权范围内读取和分析项目，直接执行代码检查与自测。委派只读分析或检查须遵守当前环境的代理规则，不借代理、格式化器、脚本或测试钩子代写代码。
- 这是项目编程分工，不改变已明确授权的工作流 Bootstrap/Upgrade 引擎事务、例行项目记忆保存和聊天身份管理。工作流维护任务若被用户明确授权直接修改，按该具体授权处理；不能将运维例外推广为业务代码代写。

## Codex 负责检查和代码自测

检查最新文件中的实际实现与目标、接口、边界情况和相关调用是否一致。不得把聊天中的建议代码当作已部署实现，也不得替换用户代码后测试一个未经用户写入的版本来报告通过。

选择与本轮变化相称的检查和已有测试，先核实命令及其副作用。检查和自测不能隐含运行自动修复、格式化写入、更新快照、生成项目源码、安装依赖或修改配置的钩子。使用非写入检查选项；必要时将自测所需的编译产物、临时测试夹具和运行输出限制在明确的隔离输出目录，且被测对象仍是用户的实际代码。

新增持久项目测试源码由用户写入；Codex 可为自测准备范围内的隔离临时夹具，不能借此把功能实现写进项目或用替代实现获得通过。自测附带的必要编译只为验证当前代码，不扩展为独立构建、环境安装或部署任务；遵守项目已有运行位置和构建限制。

工具、依赖或安全的运行方式不足时，明确指出受阻的检查、自测及原因，给用户解决步骤，不擅自安装、改文件或声称验证成功。已通过的旧结果只作历史证据。

记录本轮被测文件的检查点，测试后核对相关源文件差异。用户在运行期间改动代码时，结果只对应实际被测版本，须重新核实再报告当前版本状态；发现测试意外改写源文件时停止并如实报告，不擅自回滚覆盖用户可能同时进行的修改。

发现问题时解释实际现象、原因和建议修法，在聊天中给本轮修正片段与位置；等待用户修改，再核对真实代码并重新运行受影响的检查。不要顺手修掉问题或扩大到无关重构。

## 记录与恢复

若项目部署了 codex-project-flow，读取其计划、状态和本地 `project-workflow-manager` 技能，按既有 helper 的哈希前置条件合并保存，不手改身份登记。记录：

- 已确认的架构、接口和逻辑决定及依据；当前小目标及其完成条件。
- 已给出的代码方案与实际采用情况、相关文件位置及检查点哈希或工作区版本。
- 用户的未解疑问、已问未答问题、阻塞和下一步所需前置条件。
- 实际检查及自测的命令、运行位置、结果和未覆盖项；区分本轮与历史证据。
- 当前等待用户修改、等待用户明确继续或验证受阻的状态，以及最后一次有效继续指令对应的小目标。不要让一次继续指令跨越多个小目标或在恢复时重复使用。

普通项目没有这些文件时，在当前聊天保留必要记录，按已有授权保存到项目记录位置，不为使用本技能安装工作流或擅自创建记忆文件。例行记忆不复制完整聊天或代码大块内容。

恢复时先读记录和最新实际文件，核对用户手动修改，从当前小目标及未解问题继续；不重放历史代码覆盖当前文件，不重复已确认讨论。聊天续接和归档按现有明确授权与身份规则处理，不因等待用户或上下文占用自行创建任务。

## 本轮交付与验收

清楚区分“已给出方案”“用户已写入”“检查/自测已完成”和“用户已验收”。每轮简要交代本轮小目标、方案或实际变更、验证证据、未覆盖项，以及现在等待用户做什么。

只有用户明确验收对应完整计划步骤才按项目规则同步进度；理解一个知识点、认可接口、选择性复制、检查通过、说“继续”或进入下一小目标都不等于整个步骤验收。保持每请求唯一执行身份和既有容量、并发、屏障及恢复保护。
