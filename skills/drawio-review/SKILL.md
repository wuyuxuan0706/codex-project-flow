# Drawio 绘图与评审

## 目标与能力检查

交付可编辑、结构清晰、样式统一的 drawio 图，并让用户通过聊天图片评审每轮修改。

- 开始前明确用途、目标文件、目标 page、修改范围和主题；已有信息足够时直接推进。
- 检查当前实际可用的文件读写、drawio 渲染及聊天内图片输出能力。不要假定已安装 drawio、存在某个连接器或必然支持内存图片回传。
- 选择能从最新 drawio 内容生成效果、在内存中处理并直接回传聊天图片的路径；确认渲染过程不会自动写入本地图片、临时图片或图片缓存。默认禁止这些落盘方式，用户明确要求导出时才例外。
- 工具无法满足聊天内图片输出或无本地图片落盘要求时，说明具体缺失能力和未完成项，不擅自改为本地导出、不用替代稿冒充结果，也不声称已完成视觉检查。

## 文件与页面管理

- 用户指定已有文件时，直接编辑该文件，不擅自另存副本或创建重复文件；用户要求新建图稿时，再创建新的 `.drawio` 文件。
- 每次修改前读取最新内容，保留用户手动修改，不用历史版本覆盖当前文件。
- 默认修改目标 page；新增、删除、重命名或重组 page，必须在用户授权范围内。
- 在已有设计上局部修改，保留未涉及的页面、单元和内容；不自动恢复用户删除的内容。
- 保持图形、文字和连接线可编辑，不把整张图片嵌入后冒充可编辑图稿。
- 使用图片作为参考重建时，明确区分“参考图片重建”和“恢复原文件”；仅有图片时不得宣称恢复了原始对象、结构或连接关系。

## 范围与评审

- 新增或修改文字前，列出本轮完整文案供用户评审，包括标题、标签、字段、按钮、表头和提示；只写入已批准的文案。用户直接提供文字并要求填入时，视为该文字已获授权，不重复请求同一批准。
- 尚未批准的实质性设计变更也须先提交并等待相应确认；已有明确授权的范围直接执行。
- 用户只要求图形或样式时，使用无文字图示；已有文件中未获授权修改的文字仍须保留。
- 分别记录图形、文案和整体设计的验收状态，不把局部认可当作整体通过。
- 设计通过不自动授权编码、部署或其他实施操作。

## 绘图规范

### 布局

- 建立清晰的阅读方向和层级，按用途选择横向、纵向或分区布局。
- 同类元素统一尺寸、间距、对齐方式和内边距。
- 容器、分组和标题之间保持明确的归属关系。
- 避免文字溢出、图形重叠、过密布局和无用途的大块留白。
- 根据实际内容调整页面尺寸，避免裁切。

### 图形与样式

- 优先沿用用户认可的样式或目标产品的实际主题。
- 统一字体、字号层级、颜色、线宽和圆角。
- 用颜色和图形表达一致的含义；关键区别不能只依赖颜色。
- 示例数据、占位图形与真实信息明确区分。
- 图稿表达展示方式，不擅自将示例结构转成固定的业务规则。

### 连接线

- 使用实际图形端点建立连接，保证连接引用有效，避免连接线仅在视觉上贴近节点。
- 根据含义选择方向、箭头和标签；新增或修改标签同样先评审文案。
- 优先采用便于阅读的直线或正交折线，减少交叉和穿过文字的连线。
- 不凭位置、排列顺序或外观推断未经确认的关系。
- 修改节点位置后，检查相关连线和折点。

## 每轮操作流程

1. 读取最新文件，确定目标 page、本轮修改对象和适用授权。
2. 提交尚未批准的完整文案或实质性设计变更，等待相应确认。
3. 执行已授权修改，保留其他页面和无关单元。
4. 检查结构和视觉效果，按下列验证要求核对。
5. 在聊天中直接显示本轮效果图片，按下列图片输出要求处理。
6. 简短说明修改内容、验证结果、未覆盖项和仍需评审的部分。

用户确认后只继续相应范围；用户提出修改时，在当前最新图稿基础上迭代。

## 验证要求

- drawio 文件能够正常解析，页面结构有效。
- 同一 page 内单元 ID 唯一，父级和连接端点引用有效。
- 用户未要求修改的页面、文字、图形和连接关系保持不变。
- 核对新增或修改的文字与批准文案一致。
- 检查文字换行、遮挡、对齐、间距、连线走向和页面边界。
- 结构检查不能代替视觉检查；未完成的检查如实说明。

## 图片输出

- 每轮文字或图形修改后，将效果图片直接显示在聊天中，方便手机端评审；不只提供文件链接代替图片评审。
- 默认只在内存中生成图片，不创建、保存或缓存本地图片文件；用户明确要求导出时例外。此约束针对效果图片，不禁止写入用户已授权的可编辑 `.drawio` 目标文件。
- 图片必须依据最新 drawio 内容生成，不用旧截图或另画的替代稿作为修改结果。
- 优先使用 drawio 原生渲染；使用其他渲染方式时，说明可能存在的视觉差异。
- 局部修改优先展示清晰的局部图；跨区域修改展示全图，必要时补充局部图。
- 工具无法满足聊天内图片输出时，说明具体限制，不擅自改为本地导出。

## 每轮交付说明

简要说明修改了哪个文件和 page、本轮具体改动、已完成检查及未覆盖项，以及用户接下来需要评审什么。保持图形、文案和整体设计各自的验收状态明确，继续操作以用户确认的相应范围为准。
