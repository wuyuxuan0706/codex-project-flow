# 项目状态维护

本 Skill 只能由负责当前请求的用户可见执行任务使用；永久项目中枢不得直接调用本 Skill 修改项目状态。只维护 `.agents/workflow.json` 的 `paths.project_state`，读取项目规则、机器契约和现有状态，仅采用当前会话已确认的长期事实。

保持以下结构：

```markdown
# 项目状态
## 当前目标
## 当前进展
## 重要结论
## 下一步
```

保留仍有效内容，替换已过时内容；记录应简短、可核查，不追加流水账。没有长期变化时不改写。

修改状态文件前，执行任务必须先在当前聊天中输出修改后的完整纯文本草稿和精确路径，并等待用户明确批准。用户否决或提出修改时，在当前任务内重新生成完整草稿；不得把意见转回中枢，也不得创建另一个状态维护任务。

草稿路径或实质内容发生变化后，原批准失效。批准后只允许把已评审内容转换为符合项目规则的 Markdown，不得增加新的长期事实。写入后报告改动章节和事实来源。

输出保持 `.md`，不创建独立封面或标题页；首个非空标题为 `# 项目状态`，后续标题逐级递进且不跳级。正文按内容合理使用段落、列表、表格或代码块，并只校验本次更新的状态文档。

不得管理任务、确认需求或授权，也不得检查、构建、测试、提交、推送或执行外部操作。聊天审批、评审轮次、临时讨论、请求运行状态、用户验收决定、完整日志、交接包、轮换计数和任务 ID 都不写入项目状态；计划、代码存在和历史结果不构成本轮验证。
