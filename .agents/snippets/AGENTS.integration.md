## Codex Project Flow 集成片段

目标仓库已有根 `AGENTS.md` 时，不自动覆盖或追加。请人工合并以下规则，并保留原项目更具体、更严格的安全、构建和测试约束：

- 需要规则、执行流程或长期状态时，按 `.agents/workflow.json` 读取对应路径。
- Work 只用于只读分析、澄清和设计。
- 修改、检查、构建、测试、文档同步、提交、推送和执行任务轮换分别列为编号项，只执行用户明确选择的项目。
- 永久项目中枢不占执行任务槽；中枢之外默认最多保留一个用户可见活动执行任务，阻塞或等待仍占用该任务槽。
- 执行任务轮换只延续同一已授权范围；首选里程碑边界，第 6 个实质执行轮次开始评估，第 10 个轮次前在最近安全点轮换，上下文压力或用户请求也可触发。
- 轮换时，中枢确认交接包并生成版本化 `rotationKey`，将其作为继任首条用户消息第一行，再归档前任并创建继任；无任务 ID 的创建失败需恢复前任，只有 `clientThreadId` 时视为排队占槽且不得重试，物化后按完整键精确恢复唯一继任。
- 需求、范围、接口、协议、环境或验收标准变化时，停止执行并回到 Work 重新确认。
- 保持改动聚焦，保留并绕开工作区已有的无关改动。
- 区分文档或代码确认、静态检查、实际构建或测试、用户或外部环境回传。
- 未实际运行的检查、构建或测试不得写成通过。
- 交接包不写入项目状态；继任重新核对工作区，且不把历史验证当作本轮证据。
- 使用独立 Git worktree 时，只有已形成授权范围内的可传递代码检查点才轮换。
- 高风险操作和外部操作串行执行。
- 一次性要求不自动成为长期规则；修改规则、SOP、Prompt 或 Skill 必须明确授权。
- `docs/PROJECT_STATE.md` 只记录当前目标、当前进展、重要结论和下一步。
- 只有需要协调、要求用户选择或用户明确要求时才回传结果。
